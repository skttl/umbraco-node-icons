# Verification

The implementation was checked against Umbraco 18.0.0 on .NET 10. The solution, including the official-template SQLite demo, builds. Server tests pass 16/16; client tests pass 31/31 on both supported majors; TypeScript checking and production Vite build pass.

The built NuGet package was installed into a separate official-template 18.0.0 site using only a package reference. Startup and `/umbraco` returned HTTP 200. A temporary diagnostic endpoint confirmed automatic composer registration of the MVC result filter. The manifest, main JavaScript and hashed dynamic sign chunk all returned HTTP 200 from `/App_Plugins/NodeIcons/`. The build copied the settings schema and referenced it from `appsettings-schema.json`.

The package verification script accepts the complete artifact and rejects a missing dynamic chunk or incorrect expected version. Schema validation accepts omitted settings and valid overrides, and rejects an empty alias, a string instead of a boolean and unknown NodeIcons settings.

Native browser component checks passed all 15 cases against each separately installed 17.0.0 and 18.0.0 NuGet consumer, with no browser console errors or warnings. These covered each production entrypoint and dynamic chunk, the registered property editor manifest, native icon-picker cloning, string storage schema and symbol/color rendering, native tree sign composition, preservation of other signs and refresh after a save event. The tests used the actual consumer import maps and production API recordings. The Umbraco 18 backoffice subsequently authenticated successfully over HTTPS. Creating the Node Icon Picker data type and attaching its Plain.String property exposed a native siblings-subset response case, now fixed on both version branches. After reinstalling the patched 18.0.0 package, clicking Save in the actual editor changed Home to a star and back to its home icon without reloading. The tree updated after each save, Home retained one original icon sign and About retained none. Actual editor Save-button testing remains unverified on Umbraco 17. Selected references display only the main icon, as documented.

Additional authenticated integration checks against each installed 17.0.0 and 18.0.0 package passed 36 assertions per major using the normal HTTPS development certificate and disposable content. These covered Management API saves followed by tree/item reads, icon/sign behavior, fallbacks, color-only changes, paging, preserved flags and unchanged stored document type icons. This verifies the real save API on both majors; the later actual editor Save-button check additionally verifies Umbraco 18.

The CI command sequence also passed locally. The shared release validation self-check covers stable/prerelease tags, complete identifier rules, package/dependency major agreement, exclusive dependency intervals and positive/negative remote-branch ancestry. Checksum-verified actionlint 1.7.12 accepted both workflows. A real prerelease 18.0.1-beta.2 also passed Release build, the then-current 15 server tests, pack and the shared package verifier. Marketplace metadata validated against the current official schema. The first hosted CI run exposed a release self-check exit-code issue, now fixed on both branches. Hosted CI subsequently passed for [Umbraco 18 at commit `370e4ab`](https://github.com/skttl/umbraco-node-icons/actions/runs/42217656878) and [Umbraco 17 at commit `a3cca96`](https://github.com/skttl/umbraco-node-icons/actions/runs/42217656806). No NuGet OIDC exchange was run.

Use maintained CMS patch releases within the supported major for real deployments; no dependency overrides or audit suppression were added.

The document-type tooltip update passes 18 native browser component checks on both Umbraco 17.0.0 and 18.0.0, including a tree item with Protected, Scheduled publishing and the original-icon sign. The tooltip displays the document type name and preserves all three signs.
