# Verification

The implementation on this branch was checked against Umbraco 17.0.0 on .NET 10. The solution, including the official-template SQLite demo, builds. Server tests pass 15/15; client tests pass 10/10; TypeScript checking and production Vite build pass.

The built NuGet package was installed into a separate official-template 17.0.0 site using only a package reference. Startup and `/umbraco` returned HTTP 200. A temporary diagnostic endpoint confirmed automatic composer registration of the MVC result filter. The manifest, main JavaScript and hashed dynamic sign chunk all returned HTTP 200 from `/App_Plugins/NodeIcons/`. The build copied the settings schema and referenced it from `appsettings-schema.json`.

The package verification script accepts the complete artifact and rejects a missing dynamic chunk or incorrect expected version. Schema validation accepts omitted settings and valid overrides, and rejects an empty alias, a string instead of a boolean and unknown NodeIcons settings.

Native browser component checks passed all 15 cases against each separately installed 17.0.0 and 18.0.0 NuGet consumer, with no browser console errors or warnings. These covered each production entrypoint and dynamic chunk, the registered property editor manifest, native icon-picker cloning, string storage schema and symbol/color rendering, native tree sign composition, preservation of other signs and refresh after a save event. The tests used the actual consumer import maps and production API recordings. Actual editor Save-button testing remains outstanding following an earlier OAuth login failure in the test browser. Selected references display only the main icon, as documented.

Additional authenticated integration checks against each installed 17.0.0 and 18.0.0 package passed 36 assertions per major using the normal HTTPS development certificate and disposable content. These covered Management API saves followed by tree/item reads, icon/sign behavior, fallbacks, color-only changes, paging, preserved flags and unchanged stored document type icons. This verifies the real save API; clicking Save in the actual content editor remains unverified.

The CI command sequence also passed locally. The shared release validation self-check covers stable/prerelease tags, complete identifier rules, package/dependency major agreement, exclusive dependency intervals and positive/negative remote-branch ancestry. Checksum-verified actionlint 1.7.12 accepted both workflows. A real prerelease 18.0.1-beta.2 also passed Release build, all 15 server tests, pack and the shared package verifier. Marketplace metadata validated against the current official schema. No GitHub workflow or NuGet OIDC exchange was run.

The locked client install reports seven upstream npm vulnerabilities (one low, three moderate, two high, one critical). Minimum-version builds report upstream NuGet advisories, including CMS, SQLite and cryptography dependencies. They remain visible. Use maintained CMS patch releases within the supported major for real deployments; no dependency overrides or audit suppression were added.
